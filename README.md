# RAG Modul Kuliah

A question-answering chatbot for university course modules in PDF form. Answers come only from the uploaded documents and cite the page they were taken from. It can run fully offline on a laptop (with Ollama).

New to RAG, chunks, or embeddings? Read [`docs/konsep-rag.md`](docs/konsep-rag.md) first (in Indonesian).

## Features

- Upload a PDF (click or drag and drop), then ask about its contents. Answers include citation numbers; click a number to see the quoted passage and its source page.
- **Suggested questions** appear automatically after upload, generated by the LLM from the PDF's content. Reopen them anytime with the ⓘ button next to a document, or regenerate them with "↻ buat ulang".
- **Index panel** in the sidebar: chunk/vector count, vector dimension, embedding model, chunk size, Top-K, and the LLM in use.
- Choice of LLM: Ollama (local, free) or the Claude API.

The web UI is in Indonesian.

## How it works

```
UPLOAD:  PDF → extract text per page → chunk (800 chars, 150 overlap) → embedding → ChromaDB
ASK:     question → embedding → find top-5 most similar chunks → prompt (context + question) → LLM → answer + citations
```

| File                    | Contents                                                                |
| ----------------------- | ----------------------------------------------------------------------- |
| `app/config.py`         | Reads settings from `.env`                                              |
| `app/ingest.py`         | PDF text extraction (pypdf) and chunking                                |
| `app/store.py`          | Embedding (`multilingual-e5-small`) + ChromaDB                          |
| `app/llm.py`            | System prompt, context assembly, Ollama / Claude calls, question suggestions |
| `app/main.py`           | FastAPI endpoints + suggestion cache                                    |
| `app/static/index.html` | Web interface (single file, no build step)                              |
| `docs/konsep-rag.md`    | Explanation of RAG, chunks, embeddings, and ChromaDB (Indonesian)       |

## Requirements

- **Python 3.10 or newer** (`python --version`).
- **One LLM:**
  - **Ollama (local, free):** install from [ollama.com](https://ollama.com), then run `ollama pull qwen2.5:3b`. If you are short on RAM, use `qwen2.5:1.5b` and change `OLLAMA_MODEL` in `.env`.
  - **Claude API:** requires an API key from [console.anthropic.com](https://console.anthropic.com).
- About 3 GB of disk space for dependencies (PyTorch is large) and the embedding model.

## Setup

**Windows (PowerShell):**

```powershell
git clone https://github.com/Hesyitena/rag-modul.git
cd rag-modul
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

If `Activate.ps1` is blocked with *running scripts is disabled*, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, then activate again.

**Linux / macOS:**

```bash
git clone https://github.com/Hesyitena/rag-modul.git
cd rag-modul
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Make sure your terminal prompt shows `(.venv)` before running `pip install`, so packages don't go into your global Python.

**Using the Claude API:** in `.env`, set `LLM_PROVIDER=anthropic` and fill in `ANTHROPIC_API_KEY`. Don't commit `.env` (it is already in `.gitignore`).

## Run

```bash
uvicorn app.main:app --reload
```

Open http://localhost:8000, upload a PDF, and ask a question. Interactive API docs are at http://localhost:8000/docs.

The first run downloads the embedding model (~120 MB), so startup takes a while. After that it works offline (when using Ollama).

## Configuration

All settings live in `.env`. Each variable is explained in [`docs/konsep-rag.md` section 10](docs/konsep-rag.md#10-konfigurasi-env).

> **Important:** after changing `CHUNK_SIZE`, `CHUNK_OVERLAP`, or `EMBED_MODEL`, **re-upload all PDFs**. Stored chunks and vectors were built with the old settings and don't change on their own. You also need to restart the server whenever `.env` changes.

## Data location

All data is stored locally in `data/` (not tracked by git):

| Path                    | Contents                                |
| ----------------------- | --------------------------------------- |
| `data/uploads/`         | Copies of uploaded PDFs                 |
| `data/chroma/`          | ChromaDB vector database                |
| `data/suggestions.json` | Cached question suggestions per document |

To start from scratch: stop the server, delete the `data/` folder, and start it again.

## API

| Method | Path                            | Description                                                                         |
| ------ | ------------------------------- | ----------------------------------------------------------------------------------- |
| POST   | `/documents`                    | Upload a PDF (form-data `file`). Same name = replaces the existing document         |
| GET    | `/documents`                    | List documents with their chunk counts                                              |
| DELETE | `/documents/{name}`             | Delete a document from ChromaDB, disk, and the suggestion cache                     |
| POST   | `/ask`                          | Body `{"question": "...", "top_k": 5}`. Returns the answer + sources                |
| GET    | `/documents/{name}/suggestions` | 3 suggested questions. Served from cache if present; `?refresh=true` forces the LLM to regenerate |
| GET    | `/suggestions`                  | All cached suggestions, without calling the LLM                                     |
| GET    | `/stats`                        | Chunk/vector count, dimension, models, and retrieval settings                       |

## Troubleshooting

| Symptom                                                         | Cause and fix                                                                                         |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `Gagal memanggil LLM: ... No connection could be made` / `Connection refused` | Ollama isn't running. Open the Ollama app or run `ollama serve`                          |
| `Gagal memanggil LLM: Client error '404 Not Found'`             | Model not pulled or misspelled. Check `ollama list`, then `ollama pull <OLLAMA_MODEL>`                |
| `Tidak ada teks yang bisa diekstrak` (422)                      | Scanned (image-only) PDF. Run OCR on it first, e.g. with `ocrmypdf`                                   |
| First startup is slow / looks stuck                             | The embedding model is downloading. Wait for it to finish                                             |
| `huggingface_hub ... symlinks` or `HF_TOKEN` warning            | Safe to ignore. The model is still cached; on Windows it just uses a bit more disk space              |
| Changed `CHUNK_SIZE`/`TOP_K` but nothing changed                | Restart the server; for `CHUNK_SIZE`/`CHUNK_OVERLAP`, also re-upload the PDFs                         |
| Answers are made up / don't match the module                    | Small models don't always follow instructions. Check the citations, try a larger model, or raise `TOP_K` |
| `ModuleNotFoundError` when running `uvicorn`                    | The venv isn't active. Activate it, then run from the `rag-modul` folder                              |

## Further experiments

1. **Change `CHUNK_SIZE` / `TOP_K`.** Compare answer quality with 400 vs 1200 character chunks. Chunks that are too small cut off context; chunks that are too large make retrieval less precise.
2. **Build an eval set.** Prepare 20 questions with correct answers and source pages, then measure whether the right page lands in the top-k (_hit rate_). This gives you an objective way to compare changes.
3. **Hybrid search.** Combine vector search with BM25 (`rank_bm25`). Helps with technical terms and code that embeddings miss.
4. **Reranker.** Retrieve the top 20, then rerank with a cross-encoder (`BAAI/bge-reranker-v2-m3`) down to the top 5.
5. **Streaming answers.** Use `"stream": true` in Ollama + `StreamingResponse` in FastAPI.
6. **Chat history.** Send a few previous questions so follow-ups like "explain in more detail" make sense.
7. **OCR.** Scanned PDFs are currently rejected. Add `ocrmypdf` as a fallback.

## Limitations

- Scanned (image-only) PDFs can't be extracted without OCR.
- Tables and formulas often come out garbled from pypdf.
- 1.5–3B models still make things up sometimes, including in suggested questions. Check the citations.
- Each question stands alone; there is no conversation history yet.
